# 🔦 공포 술래잡기

불 끄고, 각자 폰 들고 하는 실시간 공포 술래잡기. 술래는 안대를 쓰고, 도망자는 폰 마이크로
술래와의 거리를 "위험도"로 느끼면서 도망 다닙니다. 스킬로 서로 방해하거나 도와줄 수 있어요.

두 가지 방식으로 돌릴 수 있어요.

- **A. 파티 당일 노트북으로 직접 실행 (LAN 모드)**: 설치 없이 바로, 그 자리 와이파이로만 동작.
- **B. 클라우드에 배포 (Render 등)**: 매번 노트북 켤 필요 없이 고정 주소로 언제든 접속.

## A. 파티 당일 노트북으로 실행 (LAN 모드)

### 준비물

- 다같이 접속할 노트북/PC 1대 (서버 역할)
- 참가자 전원의 스마트폰 (같은 와이파이에 연결)
- 안대 1개, 불 끌 수 있는 방

### 실행 방법

```bash
npm install
npm run start:lan
```

터미널에 아래처럼 접속 주소가 뜹니다.

```
https://192.168.x.x:8443
```

이 주소를 참가자들 폰 브라우저에 입력해서 접속하세요 (같은 와이파이 필수).

#### ⚠️ "안전하지 않음" 경고가 뜨는 이유

마이크 접근은 브라우저 보안 정책상 HTTPS가 필요해서, `start:lan`은 자체 서명(self-signed)
인증서를 자동 생성해서 씁니다. 공인 인증서가 아니라서 처음 접속하면 경고가 뜨는데, 아래처럼
진행하면 됩니다.

- **크롬(안드로이드)**: "고급" → "...(안전하지 않음)으로 이동"
- **사파리(iOS)**: "자세히 보기" → "이 웹 사이트 방문"

## B. 클라우드에 배포하기 (Render, 무료)

이 게임은 실시간 소켓 서버라 정적 사이트 호스팅(Netlify/Vercel 등)은 맞지 않고, Node 서버가
계속 떠있는 곳이 필요합니다. **Render**가 가장 간단합니다 (무료 티어 있음, 깃허브 연결하면
자동 배포).

1. 이 저장소를 GitHub에 올려둔 상태에서, [render.com](https://render.com) 가입 후
   "New +" → "Web Service" → 이 저장소 선택.
2. 저장소에 포함된 `render.yaml`을 Render가 인식하면 빌드/시작 명령이 자동으로 채워집니다.
   (수동 설정 시: Build Command `npm install`, Start Command `npm start`, Node 버전 22 이상)
3. 배포가 끝나면 `https://your-app-name.onrender.com` 같은 고정 주소가 생깁니다. 이 주소를
   참가자들에게 공유하면 끝 — Render가 정식 TLS 인증서를 발급해줘서 **"안전하지 않음" 경고도
   없습니다.**

> **무료 티어 주의**: 15분 정도 아무도 접속 안 하면 서버가 슬립 모드로 들어가고, 다음 접속자가
> 30~60초 정도 깨우는 지연을 겪습니다. 파티 시작 1~2분 전에 아무나 먼저 링크를 한 번 열어서
> "깨워두는" 걸 추천해요. 콜드스타트가 싫으면 Render 유료 플랜이나 Fly.io 같은 상시구동
> 플랫폼을 고려하세요.

배포판은 클라우드에 있어도 게임 방식은 똑같습니다 — 위험도는 여전히 "같은 물리적 공간에서
서로의 폰 마이크로 술래 소리를 듣는" 방식이라, 서버 위치와 무관하게 다같이 한 방에 있어야
해요. 서버는 그냥 신호를 중계할 뿐입니다.

> **참고**: 방 상태는 서버 메모리에만 저장되고 인스턴스 1개로만 동작하도록 만들어졌습니다.
> Render에서 인스턴스 개수(scaling)를 1보다 크게 올리면 안 됩니다 - 그러면 같은 방 사람들이
> 서로 다른 인스턴스에 연결돼 게임이 깨집니다.

## 게임 흐름

1. **방 만들기 / 참가하기**: 방장이 방을 만들면 4자리 코드가 나옵니다. 나머지는 그 코드로 참가.
2. **로비**: 방장이 게임 시간(3~20분)과 마이크 민감도를 설정하고 시작.
3. **역할 배정 + 튜토리얼**: 무작위로 1명이 술래, 나머지는 도망자. **자기 역할에 맞는** 조작법과
   스킬 설명만 보여줍니다 (남의 스킬은 아래에 따로).
   - 이 화면에서 "이해했어요"를 누를 때 도망자는 마이크 권한을 요청하니 반드시 허용해주세요.
4. **2단계 자동 보정** (각 4초):
   - 1단계: 다같이 **조용히** → 방의 기본 소음 측정 (위험도 0 기준)
   - 2단계: 술래 폰에서 소리가 나기 시작합니다. **다같이 술래 옆에 모인 채로** 대기 → 위험도 100 기준
5. **카운트다운**: "불 끄세요!" 신호와 함께 5초 카운트다운. 이때 흩어지면 됩니다.
6. **본게임**: 술래는 안대 착용 후 실제로 돌아다니며 사람을 찾고, 도망자는 폰의 위험도 게이지를
   보며 도망 다닙니다.
7. **잡기**: 술래가 누군가를 붙잡았다고 느끼면 **화면을 탭합니다** → 모든 도망자 폰에 진동이
   갑니다. 실제로 붙잡힌 사람이 자기 폰에서 **"저 잡혔어요"** 버튼을 눌러 스스로 인정합니다
   (술래가 안대를 써서 화면을 볼 수 없기 때문에 자율 판정 방식입니다).
8. **종료**: 모든 도망자가 잡히면 술래 승리, 제한시간까지 1명이라도 살아남으면 도망자 승리.
9. 결과 화면에서 방장이 "로비로 돌아가기"를 누르면 같은 인원으로 재시작할 수 있습니다.

## 조작법

### 술래 (안대 착용 상태)

화면을 볼 수 없으므로 **화면 전체가 하나의 버튼**입니다. 버튼을 찾을 필요 없이 아무 데나 누르면 됩니다.

| 동작 | 결과 | 진동 피드백 |
|---|---|---|
| 화면 **탭** | "잡았다!" 시도 → 도망자 전원 폰이 진동 | 짧게 1번 |
| 화면 **1.5초 꾹** | 👹 괴성 발동 | 길게 1번 |

진동 패턴이 달라서 안대를 쓴 채로도 뭐가 발동됐는지 구분됩니다.

### 도망자

위험도 게이지를 보면서 도망 다니고, 조건이 맞아 **불이 들어온 스킬 버튼**을 누릅니다.
실제로 붙잡혔을 때만 "저 잡혔어요"를 누르세요.

## 스킬

### 도망자

| 스킬 | 발동 조건 | 효과 |
|---|---|---|
| 💣 연막탄 | **위험도 50 이상**, 2회 | 나 말고 **무작위의 다른 도망자** 폰에서 3초간 비명이 터짐. 술래가 그쪽으로 달려가는 사이에 튀면 됨 |
| 🫥 잠수 | 아무때나, 1회 | **6초간 절대 안 잡힘.** 술래 손이 코앞일 때 쓰는 마지막 카드 |

### 술래

| 스킬 | 발동 조건 | 효과 |
|---|---|---|
| 👹 괴성 | 아무때나(화면 1.5초 꾹), 1회 | **모든 도망자 폰에서 동시에 비명.** 사방에서 소리가 나므로 전원 위치가 한 번에 드러남 |

두 스킬 다 "어둠 속에서 소리를 조작한다"는 같은 규칙이라 외울 게 없습니다. 연막탄은 남을 미끼로
던지고, 괴성은 전원을 한꺼번에 드러냅니다.

## 위험도(술래와의 거리)는 어떻게 계산되나요?

술래 폰이 게임 내내 **1kHz 부근의 심장박동 같은 소리**를 재생합니다. 각 도망자 폰은 마이크로
그 특정 대역의 소리 세기만 골라 들어서 "가까울수록 위험도 상승"으로 변환합니다.

> 저음(수십 Hz)을 쓰지 않는 이유: 폰 스피커는 낮은 음을 물리적으로 재생하지 못해서 아무리
> 가까이 가도 감지가 안 됩니다. 폰 스피커가 실제로 소리를 잘 내는 대역을 써야 동작합니다.

**시작 전 2단계 자동 보정**을 거칩니다. 폰 스피커 음량, 마이크 감도, 방 크기가 제각각이라
고정된 기준값으로는 어느 환경에서도 맞지 않기 때문입니다.

1. **주변 소음 측정** (4초, 다같이 조용히) → 위험도 0의 기준
2. **근접 기준점 측정** (4초, 술래 옆에 다같이 모인 채로) → 위험도 100의 기준

이 두 점 사이를 dB(로그) 스케일로 매핑합니다. 소리는 거리에 따라 로그로 감쇠하므로 이렇게 해야
거리와 자연스럽게 대응합니다. 대략 이런 느낌으로 움직입니다.

| 술래와의 거리 | 위험도 |
|---|---|
| 8m (방 반대편) | 0 |
| 3m | 40 내외 |
| 2m | 55 내외 (연막탄 열림) |
| 1m | 75 내외 |
| 코앞 | 100 |

### 감지가 잘 안 될 때

- **미디어 볼륨을 최대로.** 이게 제일 흔한 원인입니다. 소리가 작으면 감지할 신호 자체가 없어요.
- 로비의 **🎧 감지 테스트**로 파티 시작 전에 미리 확인하세요. 폰 2대로 한쪽은 [비콘 켜기],
  다른 쪽은 [측정 시작]을 누르고 멀어졌다 가까워지면서 숫자가 움직이는지 보면 됩니다.
- 2단계 보정 때 "술래 폰 소리가 잘 안 들려요" 경고가 뜨면 볼륨부터 확인하세요.
- 음악은 끄는 걸 추천합니다 (1kHz 부근만 골라 듣긴 하지만 조용할수록 정확합니다).
- 그래도 너무 둔하면 로비의 **마이크 민감도**를 올리세요 (게이지가 더 빨리 찹니다).
- 도망자 폰 화면 밝기는 낮추세요. 어두운 방에서 빛이 새면 위치가 들킵니다.

## ⚠️ 안전 수칙 (게임 내 튜토리얼 화면에도 표시됩니다)

- 시작 전 방 안의 부딪힐 물건, 날카로운 모서리, 계단 등을 미리 치우거나 확인하세요.
- 술래는 절대 뛰지 말고 천천히 걸으세요. 도망자도 급하게 뛰지 마세요.
- 다치거나 무섭거나 불편하면 언제든 "그만!"을 외쳐서 게임을 멈추세요.

## 알려진 한계

- 마이크 기반 위험도는 **근사치**입니다. 소리는 벽에 반사되고 가구에 막히므로, 벽 뒤에 있으면
  실제보다 멀게 잡히기도 합니다. 정밀한 거리 측정이 아니라 "대략 가까워지면 오른다" 정도로
  즐겨주세요 (오히려 그 불확실함이 공포에 도움이 됩니다).
- 술래가 도망자 바로 뒤에 서 있어도 폰을 등 뒤로 숨기면 감지가 약해질 수 있습니다. 술래는
  폰을 몸 앞쪽에 들고 다니는 걸 권장합니다.
- Web Bluetooth/GPS 대신 오디오(마이크) 방식을 택한 이유는 iOS/Android 브라우저에서 별도 설치 없이
  가장 안정적으로 동작하기 때문입니다.
- LAN 모드(A)는 같은 와이파이가 아니면 접속이 안 됩니다. 클라우드 배포(B)는 인터넷만 되면 어디서든
  접속 가능합니다.
- 방 정보는 서버 메모리에만 저장됩니다. LAN 모드는 노트북을 끄면, 클라우드 배포는 서버가
  재시작되면(무료 티어는 슬립 후 재시작 시) 진행 중이던 방 정보가 사라집니다.

## 프로젝트 구조

```
render.yaml    - Render 클라우드 배포용 설정
server/
  index.js     - Express + Socket.IO 서버, 이벤트 처리 (LAN_MODE로 HTTP/HTTPS 분기)
  game.js      - 방/게임 상태 관리
  skills.js    - 서버 권위 스킬 정의 (충전량/쿨다운/효과)
  gen-cert.js  - LAN 모드 HTTPS용 자체 서명 인증서 생성
public/
  index.html   - 전체 화면(로비/튜토리얼/보정/게임/결과)
  css/style.css
  js/skills.js - 클라이언트 표시용 스킬 텍스트
  js/audio.js  - 비콘 재생(1kHz), 마이크 협대역 dB 분석, 효과음 합성, 진동
  js/app.js    - 클라이언트 상태 머신 및 소켓 이벤트 처리
```
